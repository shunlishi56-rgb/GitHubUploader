
# GitHub 上传工具（GitHubUploader）

## 一、项目概述

GitHub 上传工具是一款运行于 Windows 平台的图形化代码上传工具，面向需要频繁向 GitHub 仓库推送代码、但不熟悉 Git 命令行操作的用户。工具提供两种上传模式，内置网络故障自愈、多账号凭据隔离、版本标签管理等功能，将「压缩包覆盖上传」「增量代码推送」等操作简化为双击启动、一键完成。

## 二、功能特性

| 功能 | 说明 |
|------|------|
| 覆盖上传 | 用本地新压缩包（.zip）整体替换远程仓库内容，自动处理嵌套目录结构 |
| 增量推送 | 直接提交并推送本地仓库中已修改的文件，无需完整 clone |
| 网络自愈 | 自动检测 GitHub 各节点 IP 连通性，不通时自动切换 hosts 指向可用节点 |
| 版本标签 | 覆盖上传前自动为旧版本打标签，支持任意历史版本回溯 |
| 多账号支持 | 可切换多个 GitHub 账号，凭据按账号隔离存储、互不冲突 |
| 协作仓库 | 支持以当前账号身份推送他人仓库（填写「所有者/仓库名」） |
| 配置记忆 | 自动记住最近使用的账号与仓库，下次启动自动填充 |
| 仓库自动克隆 | 本地不存在的仓库自动从 GitHub 克隆，无需手动操作 |
| 实时日志 | 执行过程逐条输出至界面日志区，异常可见可查 |
| 错误兜底 | 运行异常时自动写入错误日志文件，避免窗口闪退后无迹可寻 |

## 三、使用说明

### 3.1 启动

双击 `GitHub上传工具.bat`，按提示允许 UAC 管理员授权（修改 hosts 需要管理员权限）。

### 3.2 覆盖上传（整体替换仓库）

1. 在「上传模式」中选择「覆盖上传」
2. 填写 GitHub 账号（如 `shunlishi56-rgb`）
3. 填写目标仓库名（或「所有者/仓库名」）
4. 点击「浏览...」选择新压缩包
5. 填写版本号（如 `v2.0`）与版本说明
6. 点击「一键上传」

### 3.3 增量推送（仅提交本地改动）

1. 在「上传模式」中选择【增量推送】
2. 选择账号与本地仓库
3. 填写版本号与说明
4. 点击「一键上传」

### 3.4 新账号首次使用

- 输入新账号名后执行上传，git 会自动弹出 GitHub 登录窗口
- 输入该账号的用户名与 Personal Access Token（令牌），登录后永久记住
- 账号切换不会影响其他账号的已保存凭据

## 四、目录结构

```
GitHubUploader/
├── GitHubUploader.ps1      # 主脚本（图形界面 + 核心逻辑）
├── GitHub上传工具.bat       # 双击启动器
└── GitHub上传工具配置.json   # 运行时自动生成，记忆账号与仓库
```

## 五、技术实现

| 项目 | 说明 |
|------|------|
| 脚本语言 | PowerShell（Windows PowerShell 5.1 兼容） |
| 界面框架 | Windows Forms（System.Windows.Forms / System.Drawing） |
| 压缩处理 | System.IO.Compression（内置解压，无外部依赖） |
| Git 操作 | 调用系统 Git 命令，自动重试与网络修复 |
| 网络检测 | TCP 端口探测（443），多节点 IP 轮询 |
| 配置存储 | 本地 JSON 文件（工具目录下） |
| 凭据机制 | git credential manager + URL 携带账号名实现多账号隔离 |

## 七、已知约束

1. 本工具仅支持 HTTPS 协议的 GitHub 仓库，不支持 SSH。
2. 覆盖上传会整体替换仓库内容，旧内容不保留，但版本标签可回溯历史版本。
3. 覆盖上传需提前在本地准备 .zip 压缩包。
4. hosts 修改需要管理员权限，故首次启动须通过 UAC 授权。
5. GitHub 节点 IP 可能随网络环境变化，若推送失败工具会自动切换节点，极端情况下需联系网络服务商。
6. 私域仓库推送需账号具备对应仓库的写入权限。
